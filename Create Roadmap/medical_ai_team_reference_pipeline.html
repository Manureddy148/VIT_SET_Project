7-Layer Pipeline (Merged from Pipeline Documentation)
Each layer is independently testable and owned by clear team responsibilities.
01

Input Router

Layer 1 | Input Intelligence

Accepts text, structured clinical JSON, image files, ECG uploads, audio uploads, and genomics files. Validates and routes to modality processors.

02

Preprocessing and NER

Layer 2 | Clinical Understanding

Extracts labs from text, normalizes numeric features, infers disease domain, and prepares feature vectors with missing feature prompts.

03

Model Registry and Router

Layer 3 | Domain Model Dispatch

Registry routes prediction calls to disease models. Supports adding new disease classes and keyword registration without redesigning the pipeline.

04

Inference and Explainability

Layer 4 | Scoring and SHAP

XGBoost-style tabular inference outputs severity score (0-100), label, confidence, and SHAP top risk features used in downstream retrieval.

05

RAG Retrieval

Layer 5 | Evidence Grounding

SHAP-driven query retrieves citations from ChromaDB/PubMed corpus with domain-aware filtering and faithfulness checks.

06

LLM Synthesis and Safety

Layer 6 | Report Generation

Optional LangChain plus Groq generates structured clinical narrative with explicit safety rails and mandatory disclaimer behavior.

07

Delivery Layer

Layer 7 | API, UI, Audit

FastAPI endpoints and Streamlit dashboard deliver severity gauge, SHAP explanations, citations, streaming output, and PDF export.

Team Guide (Merged Role Ownership)
Team role structure adapted from Team Guide and aligned to current repository work.

ML Engineer (Layers 3 and 4)

  • Train and calibrate disease models.
  • Maintain SHAP explanations and feature ranking quality.
  • Version exported model artifacts and thresholds.

Backend Engineer (Layers 1, 2, 7)

  • Maintain API contracts and modality endpoints.
  • Build robust preprocessing and normalization paths.
  • Own audit logs, endpoint reliability, and schema evolution.

RAG and Knowledge Engineer (Layer 5)

  • Run PubMed ingestion and keep vector store healthy.
  • Tune retrieval quality and domain filtering behavior.
  • Track hallucination faithfulness and RAGAS metrics.

Frontend and Integration (Layers 6 and 7)

  • Maintain Streamlit UX and explanation readability.
  • Integrate report generation and PDF export workflows.
  • Run end-to-end smoke verification before demos.
