What Are We Building?

💡

Simple version: We are building a tool that a doctor or nurse types a patient's symptoms into, and gets back a clear answer — how sick is this patient, and why? The system gives a score from 0 to 100 and explains the reasoning using real medical journal articles.

The Simple Analogy

Think of it like a very experienced doctor's assistant. You describe the patient — "high blood sugar, 52 years old, BMI 34" — and it replies:


Severity Score: 74/100 — HIGH RISK (Diabetes)

Primary risk driver: elevated glucose (210 mg/dL). Supporting evidence from ADA Standards of Care 2024: "Fasting glucose above 126 mg/dL is diagnostic of diabetes..." Recommend physician review. ⚠️ Medical disclaimer applies.

The 7 Layers — What Each One Does

Every layer is independently testable and built by a different team member. Here is exactly what each one does, what goes in, and what comes out.


01
Multimodal Input Router
Layer 1 · Input Intelligence

Plain English: The front door. Accepts anything — typed text, CSV files, medical scan images, ECG files, audio, even DNA files. Checks if the data is valid and hands it to the right processor. If something important is missing, it asks the user to provide it.

Free text, CSV, DICOM images, ECG files, WAV audio, VCF genomic files

A clean, typed "payload" — structured data ready for Layer 2

Python file readers, DICOM library, missing-data dialogue agent

02
Clinical Entity Extraction (NER)
Layer 2 · Understanding

Plain English: The reader. Takes the input and pulls out the important medical facts — disease names, lab values, medications, body parts. Also detects negation ("no chest pain" = chest pain is absent). For images, normalises brightness. For ECG, detects heartbeat peaks.

"glucose 210, BMI 34, frequent urination, age 52"

{domain: "diabetes", glucose: 210, bmi: 34, age: 52, missing: ["insulin"]}

BioBERT (medical AI), NegEx algorithm, NeuroKit2 for ECG processing

03
Model Registry & Router
Layer 3 · Decision

Plain English: The switchboard. Looks at the domain (diabetes? heart? pneumonia?) and picks the correct AI model. Think of it like dialing the right specialist. Adding a new disease later doesn't require changing this layer — just register a new model.

Domain name from Layer 2: "diabetes"

The correct XGBoost model, loaded and ready to run

Python class registry, joblib model loader, domain keyword matcher

04
Severity Inference + SHAP Explainer
Layer 4 · Prediction

Plain English: The calculator + receipt. The ML model runs the patient's numbers and outputs a severity score 0–100. SHAP then produces a "receipt" showing exactly which features caused the score — like: glucose drove it up 32 points, BMI drove it up 18 points, age added 12. This is why doctors can trust it.

Feature array: [210, 34, 52, 72 ...] (all the patient's numbers)

severity_score=74, label="High", shap={glucose:+0.42, bmi:+0.28, age:+0.15}

XGBoost (trained model), SHAP library, severity calibration formula

05
RAG Knowledge Base
Layer 5 · Evidence

Plain English: The smart library. RAG = Retrieval-Augmented Generation. We pre-loaded 500+ real medical journal abstracts into a searchable database. When SHAP says "glucose was the top risk factor", this layer searches the library for papers about high glucose + diabetes. A faithfulness checker makes sure the AI only cites what it actually found — no made-up references.

SHAP-generated query: "diabetes elevated glucose high BMI clinical risk"

Top 3–5 real paper excerpts + their source names

ChromaDB (vector database), sentence-transformers, RAGAS faithfulness checker

06
LLM Report Generator + Safety Rails
Layer 6 · Writing

Plain English: The writer with rules. Llama 3 (a free AI like ChatGPT) writes the final report using the score, SHAP explanation, and retrieved papers. Hardcoded safety rules: never suggest drug doses, always say "consult a doctor", automatically flag Critical scores as urgent. It can only reference the papers that were actually retrieved — not anything made up.

Score=74, top features, 3 paper excerpts, original patient query

A full written explanation: summary, risk factors, evidence, safety disclaimer

Llama-3-8B via Groq API (free), LangChain prompt template, safety filters

07
FastAPI Backend + Streamlit UI
Layer 7 · Delivery

Plain English: The delivery window. FastAPI creates a web address (/predict) that any app can call to get a prediction. Streamlit creates the visual screen doctors see — severity gauge, bar chart of what caused the score, clickable paper citations, and the full report. Docker makes it easy to deploy anywhere.

The final structured report + score from Layer 6

JSON API response for developers / visual dashboard for doctors

FastAPI, Streamlit, Docker, GCP Cloud Run (deployment)

Week 1 — What To Do First

Do these steps in order. Do not skip ahead. Each step builds on the one before it.


Day 1
Create the GitHub repository
Go to github.com → New Repository → name it medical-ai-severity → clone to everyone's laptop. This is where ALL code lives. Everyone pushes here daily.
Day 1
Create the folder structure
Create: src/, data/, notebooks/, models/, tests/. Add a .gitignore so large data files don't get committed. Add the requirements.txt.
Day 2
Install Python packages
pip install xgboost shap chromadb sentence-transformers fastapi uvicorn langchain langchain-groq streamlit — Run this on every team member's machine.
Day 2
Run the smoke test
Download medical_ai_e2e.py from the repo. Run: python medical_ai_e2e.py. You should see ✅ PASS for all tests. This proves your setup works.
Days 3–4
Download the Kaggle datasets
Go to kaggle.com. Download: Pima Indians Diabetes, Heart Disease UCI, Chest X-Ray Pneumonia. Put them in data/raw/. Do not commit them to GitHub (they're in .gitignore).
Days 4–5
Open your first Jupyter notebook
Open notebooks/01_eda_diabetes.ipynb. Load the CSV. Run df.head(), df.describe(), check for missing values, plot the glucose histogram. This is EDA — getting to know your data.
Day 5
Get your free Groq API key
Go to console.groq.com → Sign up → Create API key. Create a .env file: GROQ_API_KEY=your_key_here. This gives you free Llama 3 (14,400 requests/day).

Glossary — Technical Words in Plain English

Pipeline
The full sequence of steps from input to output. Like an assembly line in a factory.
Layer
One step in the pipeline. Each layer does one specific job and passes its output to the next.
XGBoost
A machine learning model that works great with numbers in tables (like patient lab values). It learned patterns from thousands of patient records.
SHAP
Shows WHY the model gave a certain score. Like a receipt: "glucose caused +32 points, BMI caused +18 points..."
RAG
Retrieval-Augmented Generation. The system looks up real medical papers BEFORE writing the report, so it doesn't make facts up.
Vector Database
A database that stores text as numbers so you can search by meaning, not just exact words. "Heart attack" finds papers about "cardiac arrest" too.
ChromaDB
The specific vector database we use. Stores all our medical paper embeddings and lets us search them fast.
LLM
Large Language Model. The AI that reads and writes text — like GPT-4 or Llama 3. We use it to write the final clinical report.
LangChain
A Python library that helps connect LLMs to tools, databases, and other code. It's the "glue" of our pipeline.
FastAPI
A Python library for creating web APIs. It lets other programs call our AI at a URL like /predict and get a JSON answer.
Streamlit
A Python library that turns Python code into a web dashboard. No HTML or CSS needed — you write Python and it makes a visual interface.
DICOM
The file format used by CT scanners, MRI machines, and X-ray machines. Like a JPEG but for medical images with patient metadata.
EDA
Exploratory Data Analysis. Opening a dataset and looking at it — checking for missing values, unusual numbers, plotting histograms. Do this before any modelling.
RAGAS
A library that checks if our AI report is grounded in real retrieved evidence (faithfulness score 0–1). Prevents hallucination.
Hallucination
When an AI makes up a fact that sounds true but isn't. We prevent this using RAG (only cite retrieved papers) + RAGAS (verify it).
Smoke Test
A quick test to check everything is connected and working before doing detailed testing. Run `python medical_ai_e2e.py` to see all checks.
NER
Named Entity Recognition. AI reading text and labelling the important parts: drug names, lab values, disease names, body parts.
Groq
A free AI API service. We use it to run Llama 3 for free (14,400 requests/day). Sign up at console.groq.com.
Severity Score
Our main output: a number 0–100 representing how serious a patient's condition is. 0=healthy, 100=critical. More useful than just "yes/no".
Docker
A tool that packages your code and all its dependencies into a "container" that runs the same on any computer or server.
